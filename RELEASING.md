# Releasing Meyaj

This repository is published from the `meyaj_app/` directory. All paths below are relative to that directory, which becomes the repository root.

## 1. Prepare version 0.1.0

Before changing the version in future releases, update it consistently in:

- `package.json`
- `package-lock.json` (root package entry)
- `src-tauri/Cargo.toml`
- `src-tauri/Cargo.lock` (`cargo update -p meyaj` or the next build)
- `src-tauri/tauri.conf.json`

For the first release, the current value is already `0.1.0`.

The public author metadata is `Jorge A. Tzec-Interián` in `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, and `NOTICE`. Keep those values consistent and regenerate the installers after changing them.

## 2. Validate

Run from the repository root:

```sh
npm test
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

Check that `LICENSE`, `NOTICE`, and `THIRD_PARTY_NOTICES.txt` are present and review the license/credits section in Settings.

## 3. Build the Windows x64 installer

```sh
npm run release:windows
```

This regenerates `THIRD_PARTY_NOTICES.txt` and builds the per-user NSIS installer.

Expected artifact:

```text
src-tauri/target/release/bundle/nsis/Meyaj_0.1.0_x64-setup.exe
```

The installer currently has **no code-signing certificate**. Windows SmartScreen can therefore display an “Unknown publisher” warning. Do not describe it as signed or trusted until a certificate is configured and the installer is re-signed.

Generate the checksum announced with the release:

```powershell
certutil -hashfile .\src-tauri\target\release\bundle\nsis\Meyaj_0.1.0_x64-setup.exe SHA256
```

Test the installer on a clean Windows x64 machine or virtual machine. Verify first launch, the logo, Settings → **About Meyaj**, import of both public examples, task creation, completion rules, and uninstall.

## 4. Publish the source to GitHub

Create an empty repository named **meyaj_task_workspace** without a README, license, or `.gitignore` generated by GitHub. From the directory that will become the repository root:

```sh
git init
git add .
git status
```

Before committing, confirm that `node_modules/`, `dist/`, `src-tauri/target/`, databases (`*.db`, `*.sqlite*`), `.env*`, private imports, and local task data are **not** staged. The repository ignore rules cover these, but `git status` is the final check.

```sh
git commit -m "Initial release of Meyaj 0.1.0"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/meyaj_task_workspace.git
git push -u origin main
```

Never add a personal task database or a private Markdown import to the public repository.

## 5. Create the GitHub release

Tag the exact validated commit:

```sh
git tag -a v0.1.0 -m "Meyaj 0.1.0"
git push origin v0.1.0
```

On GitHub, open **Releases → Draft a new release**:

1. Choose tag `v0.1.0`.
2. Title it `Meyaj 0.1.0`.
3. Use [`RELEASE_NOTES.md`](RELEASE_NOTES.md) as the release description and verify its checksum against the rebuilt artifact.
4. Attach `Meyaj_0.1.0_x64-setup.exe` and `SHA256SUMS.txt`.
5. Publish the release.

The web interface is sufficient and does not require extra tooling.

If GitHub CLI is installed and authenticated, the equivalent command is:

```sh
gh release create v0.1.0 \
  "src-tauri/target/release/bundle/nsis/Meyaj_0.1.0_x64-setup.exe" \
  "src-tauri/target/release/bundle/nsis/SHA256SUMS.txt" \
  --title "Meyaj 0.1.0" \
  --notes-file RELEASE_NOTES.md
```

If `gh` is missing, install it with `winget install --id GitHub.cli`, start a new terminal, and run `gh auth login`.

Update the checksum in `RELEASE_NOTES.md` whenever the installer is rebuilt for the same version.

## 6. macOS

A macOS DMG **cannot be cross-compiled reliably from Windows**. Build it on a Mac with Xcode Command Line Tools and the Tauri prerequisites:

```sh
npm ci
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm run tauri -- build --bundles dmg --target universal-apple-darwin
```

The universal DMG is produced under `src-tauri/target/universal-apple-darwin/release/bundle/dmg/`. Without Apple Developer ID signing and notarization, Gatekeeper will warn and users may need to right-click **Open**. For a normal public macOS distribution, configure signing and notarization credentials in `tauri build` and validate on a clean Mac.

A GitHub Actions `macos-latest` runner can also produce an unsigned DMG. It cannot provide a trusted macOS release without the Apple signing and notarization secrets.

## 7. Post-release check

Download the published `.exe` from the release page, verify its checksum, install it on a clean Windows system, and open **Settings → About Meyaj** to confirm that `LICENSE`, `NOTICE`, and the attribution are included.
